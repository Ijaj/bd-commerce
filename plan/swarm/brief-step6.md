## Decisions (do not re-ask)

- C56: flash qty is **capped**: cart refuses qty above what is left at flash price / the buyer's personal allowance (`flashAllowance`). If the buyer's allowance is 0 (limit used up) they simply pay the normal price. No split lines.
- C57: all eligible **auto** coupons that stack with each other + **at most 1 typed code**; a 2nd code only if both coupons have `stacksWithOtherCoupons`. Cart stores `couponCodes` (max 2).
- C58: bulk sale tool writes variant sale prices, undoable.
- Price order: base → sale/flash (lowest) → auto coupons → code coupon(s) → delivery. Discounts apply sequentially on what is left of each line; a line never goes below 0. `stacksWithSalePrice=false` (default) means the coupon ignores lines whose `priceSource !== 'base'`.
- Percent = floor(eligible × bp / 10000), capped by `maxDiscountP`. Allocation to lines is proportional with largest-remainder so allocations sum exactly. Refund of a line = `(lineTotal − discountP)` scaled by qty (lead updates `lineRefundP`).
- Q90: cancel (and failed delivery) reverses redemptions: restores uses, budget, bulk code, flash stock.

## Agent A — engine + cart + checkout (owns `src/promotions/engine/**`, `src/promotions/promotions.module.ts`, `src/cart/**`, `src/checkout/**`, `src/orders/orders.dto.ts` + `orders.service.ts` + `orders.controller.ts` (additive fields only), `src/orders-admin/orders-admin.dto.ts` + `orders-admin.service.ts` + `order-lookup.ts` (additive fields only), tests `test/promotions-engine*.test.ts`, `test/cart*.test.ts`, `test/checkout*.test.ts`, `test/orders*.test.ts`)

1. **Engine** (`engine/`): pure `evaluate(candidates, ctx, usage)` (no DB) + `PromotionsService.evaluate(db, ctx)` loading candidates (active auto coupons in window + coupons matching `ctx.codes`: `coupons.code` or `coupon_codes.code`, case-insensitive) and usage counts (redemptions status=applied by customer/phone/device, totals, first-order, last order date), returning `PromoResult`. Rules:
   - Eligible: status active, window, platform (both|ctx), `paymentMethods` empty or has ctx method, zone (`CouponZone` rows; none = any; for free_delivery these are the zones where delivery is waived), segment (all; first_order = no non-cancelled order by that customer/phone; specific = in `CouponCustomer` or the bulk code's `assignedCustomerId`, guests → `LOGIN_REQUIRED`; inactive_days = no non-cancelled order in `segmentParam` days), limits (total, per customer, per phone, per device/visitor, budget cap: `discountGivenP + this > budgetCapP` → `BUDGET_REACHED`), bulk code unused.
   - Scope: lines matching include targets (none = all lines) minus exclude targets (product/brand/category; category matches via `PromoLine.categoryIds`); drop non-base lines unless `stacksWithSalePrice`. `minOrderP`/`minQty` are checked on the eligible lines (after earlier discounts).
   - Types: percent; fixed (≤ eligible total); tiered (`CouponTier`, best tier with `minSpendP ≤ eligible total`); free_delivery (waives up to `deliveryChargeP` left; `maxDiscountP` caps); bxgy (per `bxgyConfigSchema`: per `buyQty+getQty` group, the cheapest `getQty` eligible units get `getPctBp` off; `getSame=false` → "get" units come from `getProductIds` lines); bundle (`bundleConfigSchema`: number of full sets = min over items of lines qty / item qty; discount = sets × (sum item unit prices − priceP), ≥ 0).
   - Combining (C57): autos sorted by `priority` desc then standalone discount desc; add one if it and every already chosen coupon have `stacksWithOtherCoupons`, or nothing chosen yet. Typed codes are processed in order: a code applies after autos if it and all chosen coupons stack; else it replaces the autos only if its standalone discount is larger than the autos' total, otherwise rejected `NOT_STACKABLE`. Max 2 codes. Rejected codes are returned, never thrown.
   - Unit tests for every type, scope, stacking, limit, rounding/allocation (no DB, many cases) plus DB-backed `PromotionsService` tests.
2. **Redemption**: `PromotionsService.redeem(tx, orderId, ctx, result)` inside the order transaction: `SELECT … FOR UPDATE` the coupon rows (sorted by id), re-check limits/budget/bulk code against fresh counts (throw `COUPON_LIMIT` 409 `CommerceError` if a limit was taken meanwhile), insert `CouponRedemption` (customerId, phone = guestPhone ?? customer phone, visitorId), bump `usesCount` + `discountGivenP`, set `CouponCode.usedAt`. `PromotionsService.reverse(tx, orderId)` (export as a plain function too: `reversePromotions(tx, orderId)`): redemptions → `reversed`, decrement counters, clear `usedAt`, call `releaseFlash`. Lead wires `reverse` into the order-cancel transition: keep it idempotent.
3. **Cart**: `CartService.lines` uses `activeFlashFor` + `effectivePrice(v, now, flash)` and per-buyer allowance (`flashUsedBy` with the cart's customer/visitor + customer phone): `priceSource` may be `flash`; `maxQty` = min(existing, flash allowance) when the line is at flash price; `setQty` over it → 409 `FLASH_LIMIT` "Only N left at flash price". Cart view adds per line `flashEndsAt: string|null`, `discountP`; top-level `discountP` (auto+code item discounts), `appliedCoupons: {couponId,name,kind,type,code,amountP,freeDelivery:boolean}[]`, `codes: string[]`, `rejectedCodes: {code,reason}[]` (rejected codes are removed from `Cart.couponCodes`). New endpoints (customer or visitor identity, same guards as cart): `POST /v1/cart/coupon {code}` → CartView, or 422 `COUPON_INVALID` with `reason` in the body when the code cannot apply to this cart right now; `DELETE /v1/cart/coupon/:code` → CartView; `GET /v1/cart/coupon-suggestions` → `{couponId,name,code:string|null,savingP,source:'wallet'|'public'}[]` best first (wallet + public code coupons + bulk codes assigned to the customer, evaluated as a dry run on the current cart; max 5). `mergeGuest` merges codes. Existing cart tests must keep passing.
4. **Checkout**: `quote` adds `autoDiscountP`, `couponDiscountP`, `appliedCoupons`, and `deliveryDiscountP` now includes coupon delivery discounts; `grandTotalP = subtotal − item discounts + delivery − deliveryDiscount`. `place`: evaluate in the tx, claim flash stock (`claimFlash`, ordered), store `Order.autoDiscountP/couponDiscountP/deliveryDiscountP/discountsJson`, `OrderItem.discountP` (from `lineDiscounts`), `priceSource`, `flashSaleItemId`; per-customer flash limit re-checked with guest phone (`FLASH_LIMIT`); `redeem`; everything idempotent like today. OTP threshold and guest limits use the discounted total. Customer + admin order DTOs expose `autoDiscountP`, `couponDiscountP`, `discounts: OrderDiscountSnapshot[]`, items `discountP`.
5. Tests: cart flash cap, apply/remove code, rejected code dropped, checkout with auto + code + free delivery, flash claim sold-out race (two placements), limits, cancel → reverse (call `reversePromotions` directly in the test; lead wires the hook).
