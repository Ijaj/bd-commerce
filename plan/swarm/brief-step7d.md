Rules: editable only while status in `processing|on_hold|pending_payment` and no shipment in `booked|handed_over|in_transit|delivered|failed|returning|returned` (else 409 `ORDER_NOT_EDITABLE` / `SHIPMENT_BOOKED`). Local shipments (`pending|awaiting_supplier|supplier_confirmed|ready`) are set to `cancelled` by a saved edit (staff re-create them). Saving = one tx under the order row lock: reverse old promotions, re-evaluate like a fresh cart for the new lines + ship-to (every line re-priced at current price/sale/flash, current coupons from `discountsJson`; a coupon that no longer qualifies is dropped and listed in `warnings`), recompute zone + delivery charge from the new upazila/area, `inventory.move` the reserve deltas per variant (order_reserve / order_release), `adjustSoldCount` by qty delta, update order totals + `codDueP` (= grand - paid), rewrite lines (removed line = delete when never shipped), write `OrderEdit` (before/after = `{ship, lines[{variantId,title,qty,unitPriceP,lineTotalP,discountP}], money, discounts}`), then `orderNotify.event(id,'edited',{editId})`. Stock short -> 409 `STOCK_SHORT {variantId}`, flash limit -> 409 `FLASH_LIMIT`, zero lines -> 422 `EMPTY_ORDER` (use cancel), unknown/archived variant -> 422 `VARIANT_UNAVAILABLE`, unserviceable address -> 422 `ADDRESS_UNSERVICEABLE`.

Endpoints (`/v1/admin/orders`, key = uuid or order no like the others):
1. `POST /:id/edit/preview` (`orders.edit`) body `EditInput`, no writes.
2. `POST /:id/edit` (`orders.edit`) body `EditInput` -> `{order: OrdersAdminDetailDto, edit: {id, createdAt}}`.
3. `GET /:id/edits` (`orders.view`) -> `{items: [{id, createdAt, staff: {id,name}|null, note, customerNotifiedAt, before, after}]}` newest first.
4. `GET /v1/admin/couriers` (`orders.view`) -> `[{id, code, name, isActive}]` (lets the filter and shipments UI stop hardcoding).
```
EditInput = { lines?: {orderItemId?: uuid; variantId?: uuid; qty: int >= 0}[]  // desired full list; existing line = orderItemId (+qty, 0 = remove); new line = variantId, qty >= 1
  ship?: {name?; phone?; upazilaId?: int; areaId?: int|null; line?; landmark?: string|null}
  customerNote?: string|null; note?: string (reason, <= 500) }       // omitted = unchanged
Preview = { lines: {orderItemId: uuid|null; variantId; title; sku; optionsText; qty; unitPriceP; lineTotalP; discountP; change: 'same'|'qty'|'price'|'added'|'removed'}[],
  money: {subtotalP; autoDiscountP; couponDiscountP; deliveryChargeP; deliveryDiscountP; grandTotalP; codDueP}, before: same money, zone: {id; name}, warnings: string[] }
```

**A5 failed delivery (C87)** design:

New rule after the usual derivation: if some shipment is `failed|returning|returned` (not received back), none is `handed_over|in_transit`, and delivered qty < active qty -> `delivery_failed`; while a sibling still moves the order stays `shipped|partially_shipped`. `failed` is terminal, never recomputed. Sync/webhook already call `recompute`; after their tx commits call `orderNotify.event(orderId,'delivery_failed')` when the order newly entered `delivery_failed`.
- `POST /v1/admin/shipments/:id/received-back` (`shipments.manage`) `{note?: string <= 300; reship?: boolean = false}` -> shipment view. Then:
  - `reship=true`: also reserve again (`reservedDelta +qty`), create a new shipment (copy items, `codAmountP`, `deliveryChargeShareP`, status `ready`, no courier) via the existing creation helper; order recomputes to `processing|partially_shipped`. No promotion/sold_count change.
  - `reship=false`: per shipment item `OrderItem.qtyCancelled += qty` and `adjustSoldCount(-qty)`; if active qty of the order becomes 0 -> `reversePromotions`, `Order.failedReason = note ?? 'delivery_failed'`, transition to `failed` (actor staff, history note); else `recompute` (other shipments decide; promotions stay, partial refund is a staff step; mention in the response `warnings`).
  - Nothing happens to stock/promotions automatically on a courier "returned" (only `received-back` does).
- Admin shipments screens (`plan/mockups/admin/orders.html`/`order.html` have no such screen, follow the existing shipments queue style): failed/returning/returned shipments get a "Received back" action (confirm modal: note, checkbox "Re-ship these items" = `reship`), and a "Delivery failed" filter chip/count; shipment detail shows who received it back and when.
