## API map (read the DTO files for exact shapes; use generated types from `@bdc/api-client`)

All under `/v1`. DTOs: `apps/api/src/{orders-admin,shipments,documents,returns}/*.dto.ts`. Controllers show perms.

- Orders (`orders-admin.controller.ts`, perms orders.view/manage/call): `GET /admin/orders` (list + filters), `GET /admin/orders/:id`, `POST :id/hold|resume|cancel|call`.
- Call queue: `GET /admin/call-queue`, `GET /admin/call-queue/count` (pending number; needs orders.call). Outcomes: confirmed / unreachable / cancelled via `POST /admin/orders/:id/call`.
- Shipments (`shipments.controller.ts`, perm shipments.manage): `GET /admin/orders/:id/shipments`, `POST /admin/orders/:id/shipments` (create; split by item quantities), `GET /admin/shipments`, `GET /admin/shipments/:id`, `POST shipments/:id/cancel|book|rebook|handover|sync`. Real couriers (Steadfast/Pathao) cannot cancel via API → cancel returns/needs `manualCancel` (read the DTO + `shipments.errors.ts`; UI offers "Mark cancelled manually" with confirmation).
- Documents (`documents.controller.ts`): `POST /admin/orders/:id/invoice` (issue), `GET /admin/orders/:id/invoices`, `GET /admin/invoices/:id` (JSON print data), `GET /admin/shipments/:id/label`, `POST /admin/shipments/labels` (bulk, max 50 ids). Customer: `GET /customer/orders/:orderNo/invoice` (delivered orders).
- Returns/refunds (`returns.controller.ts`; perms returns.manage, refunds.manage, refunds.approve): `POST /admin/orders/:id/returns`, `GET /admin/returns[/:id]`, `POST returns/:id/approve|reject|pickup-booked|receive|inspect|close|refund`, `POST /admin/orders/:id/refund`, `GET /admin/refunds[/:id]`, `POST refunds/:id/approve|reject|complete`. Customer: `POST|GET /customer/returns`, `GET /customer/returns/:returnNo`.

## Integration contract (lead pre-created stubs; owners replace them)

The order detail page (agent ORDERS) embeds three sections with identical props `{ orderId: string }`:

- `~/features/shipments/OrderShipmentsSection` → `OrderShipmentsSection` (owner SHIP) — list shipments of the order, create/split shipment, book/rebook/cancel/handover/sync actions, links to label print.
- `~/features/documents/OrderInvoicesSection` → `OrderInvoicesSection` (owner SHIP) — list invoices, issue invoice, open print view.
- `~/features/returns/OrderReturnsSection` → `OrderReturnsSection` (owner RET) — list returns/refunds of the order, "Create return" / "Refund" buttons, links to `/returns/$id`.

Routes (file names under `routes/_app/`; lead adds nav): `orders.index.tsx` `/orders`, `orders.$id.tsx` `/orders/$id` (ORDERS); `call-queue.tsx` `/call-queue` (ORDERS); `shipments.index.tsx` `/shipments` (SHIP); `returns.index.tsx` `/returns`, `returns.$id.tsx` `/returns/$id`, `refunds.index.tsx` `/refunds` (RET). Print views (SHIP): pathless layout `routes/_print.tsx` (same auth guard as `_app.tsx`, but NO sidebar/shell, white background, `@media print` rules, "Print" + "Back" buttons hidden on print) with `_print/print.invoice.$id.tsx` → `/print/invoice/$id`, `_print/print.label.$id.tsx` → `/print/label/$id`, `_print/print.labels.tsx` → `/print/labels?ids=a,b,c` (bulk, max 50, 4x6in each on its own page).
